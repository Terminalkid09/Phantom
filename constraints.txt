# constraints.txt — the VERIFIED version set, pinned.
#
# Why this file exists
# --------------------
# requirements.txt carries FLOORS (>=) on purpose: it is what CI and the
# installers use, and it must accept a range so a security patch upstream is
# not blocked by a stale pin. The cost of that choice is that two installs a
# month apart can produce different environments, and a red build caused by
# an upstream minor release reads as a product regression.
#
# This file is the other half: the exact versions the suite has been verified
# against. It is OPT-IN, so nothing changes for CI or for the one-line
# installers — but an operator who wants the verified tree reproduces it with
#
#     pip install -r requirements.txt -r requirements-dev.txt -c constraints.txt
#
# Regenerate after a deliberate upgrade:
#     python -m pip freeze | grep -iE '^(rich|requests|...)='
# and re-run the suite before committing the new numbers.
#
# NOTE: a constraint may only NARROW a requirement, never widen it. Every pin
# below satisfies the floor declared in requirements.txt / requirements-dev.txt.
