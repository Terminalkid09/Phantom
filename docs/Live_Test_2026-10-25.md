## 3. Bounded AUTO runs

Two bounded runs were started with an explicit scope
(`session.scope = ["192.168.1.18"]`), `goal=footprint`, `stealth=True`,
`exploit_all=True`:

1. **300 s bound** — the chain scanned, probed, entered recovery/re-arming,
   and was stopped by the external bound. No exploitation attempt, no
   compromise.
2. **900 s bound** — the agent reached the bounded full-range scan
   (`nmap -Pn -sT -p 1-65535 -T2 --min-rate 500 --max-retries 1
   --host-timeout 200s`). The scan did **not** return within the host bound
   on this filtered target; the run was terminated by the external bound
   after several minutes and the WSL nmap child was killed manually. No
   execution happened.

Residual: when the parent run is killed abruptly, the Linux child inside the
`wsl.exe` wrapper can survive it. It is recorded here rather than hidden; the
operator must verify `wsl ps` after an aborted scan.

## 4. Generic CVE intake (no per-CVE code)

Validated with a real child-process PoC in a temporary lab directory:

- `attempt_cve("CVE-2099-99999", ...)` resolved the PoC from the local
  library, ran it in the child interpreter, classified
  `VULNERABLE (RCE) uid=0(root)`, and wrote an evidence-backed
  `exploit_packs.json` entry with status `verified`.
- A fresh CVE with an ExploitDB MSF module becomes an actionable candidate
  with no Phantom code change; a high-severity exact match with no known
  weapon becomes a bounded intake candidate and asks the live MSF index once.
- Three negative attempts retire a pack (`deprecated`) and remove it from
  automatic selection; a verified pack gets a ranking bonus on the next run.
- **Windows MSF discovery was broken and is fixed:** `search_module_for_cve`
  now falls back to the Kali WSL wrapper. Live check:
  `CVE-2021-41773` → `exploit/multi/http/apache_normalize_path_rce`.
- **A CVE Phantom had never seen resolves live, with no code or pack
  change:** `CVE-2024-3400` →
  `exploit/linux/http/panos_telemetry_cmd_exec` and `CVE-2024-1709` →
  `exploit/multi/http/connectwise_screenconnect_rce_cve_2024_1709`, both via
  the live `msfconsole search cve:<id>` index (`source=msf_search`,
  `status=candidate`). This is the general behaviour a new PHP2Shell-class
  CVE would hit: the intake resolves the weapon at run time, then evidence
  promotes the pack.
- No arbitrary GitHub PoC is downloaded or executed; a new vulnerability is
  only exploited through a module path or PoC that is already on disk.

No live target with a fresh CVE was available on `.18`; the honest result for
such a CVE is `knowledge-only` until a weapon exists. That is a deliberate
limit, not a failure.
